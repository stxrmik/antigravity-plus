# Antigravity Plus

Claude Code-style engineering discipline plugin for **Google Antigravity 2.x** (36 skills, 7 subagents, 6 hooks, a 19-tool bundled stdio MCP server, always-on rules, and a 4-tab Control Center sidecar), installed whole or as chosen **modules** (`modules.py`), plus a two-way **Claude Code ↔ Antigravity** bridge (`claude-code/skills/antigravity` and `antigravity-plus/skills/claude`). Pure Python 3.8+ standard library (plus bundled Node 24 for the usage sidecar), cross-platform across macOS, Linux, and Windows.

## Commands
- Install / update into `~/.gemini/config/plugins/antigravity-plus`: `./install.sh` (Windows: `.\install.cmd`, or `python3 install.py`); modules: `--choose` (menu), `--list`, `--modules core,git`, `--without mobile`, `--all`; the choice is saved in `~/.gemini/antigravity-plus/modules.json`. The `claude` module installs the Claude Code skill into `~/.claude/skills/antigravity` when `~/.claude` exists (`--no-claude` skips it)
- Delegation bridge (Claude Code → Antigravity): `python3 claude-code/skills/antigravity/scripts/delegate.py budget [--claude-5h PCT] [--claude-week PCT]` (limits on both sides, tier picks, advice; also `models`, `run`, `wait`, `watch`, `reply`, `result`, `diff`, `send`, `cancel`, `list`, `statusline`; the delegated agent itself runs `ask` / `tell`). Reverse (Antigravity → Claude Code): `antigravity-plus/skills/claude/scripts/claude_task.py` (`budget`, `run`, `wait`, `result`, `diff`, `send`, `cancel`, `list`)
- Update to the newest release: `./install.sh --update` (= `/update` in Antigravity: `antigravity-plus/skills/update/scripts/update.py run`; also `status`, `check`, `rollback`)
- Uninstall: `./install.sh --uninstall` (`--purge` also deletes `~/.gemini/antigravity-plus`)
- Test all (offline, isolated temporary `HOME`): `python3 tests/run_tests.py`
- Single test suite: `python3 tests/run_tests.py test_speed` (any `tests/test_<name>.py` without `.py`)
- Replay hooks over real transcripts / live smoke harness: `python3 tests/replay.py [--limit 25] [--save ... --compare ...]` and `python3 tests/live_smoke.py [--only ...]`
- Plugin health & install check: `python3 antigravity-plus/skills/doctor/scripts/doctor.py` · post-install diff check: `python3 antigravity-plus/skills/doctor/scripts/doctor.py --install-check`
- Token usage, context & insights CLIs: `python3 antigravity-plus/skills/usage/scripts/usage.py --all --days 7` · `context.py` · `insights.py`
- Code navigation through language servers: `python3 antigravity-plus/skills/lsp/scripts/lsp.py servers` (also `def`, `refs`, `calls`, `hover`, `impl`, `type`, `symbols`, `find`, `check`, `rename`, `status`, `stop`)

## Architecture
- `antigravity-plus/plugin.json`, `antigravity-plus/hooks.json`, & `antigravity-plus/mcp_config.json` — plugin manifest, hook wiring (`SessionStart`, `PreInvocation`, `PreToolUse`, `PostToolUse`, `Stop`), and bundled MCP server registration (`antigravity-plus_tools`). `install.py` rewrites `python3` in the installed `hooks.json` and `mcp_config.json` to `py -3 -X utf8` on Windows.
- `antigravity-plus/mcp/server.py` — stdio JSON-RPC 2.0 MCP server exposing 19 typed tools (`lsp_*`, `ci_status`, `ci_failure_logs`, `deps_audit`, `ui_check`, `mobile_ui`, `mobile_act`, `memory_search`, `git_state`, and `quota`); `tools/list` offers only tools whose script is installed, each tool's time limit is its script's worst case (`AGP_MCP_TIMEOUT` caps them all — tests set it), and a timed-out tool returns what it printed so far.
- `antigravity-plus/hooks/` — runtime hooks and shared state (`~/.gemini/antigravity-plus/state/`):
  - `session_start.py` — git snapshot, project rules (`AGENTS.md` / `CLAUDE.md` bridge), recent conversations, memory index, sandbox memory, mobile & CI workflow detection, plus zero-token `user_markdown` update banners (`uiNotices`).
  - `instructions.py` — `PreInvocation` dispatcher (emits `systemMessage`, plus zero-token `metadata.user_markdown` UI notices): re-injects user constraints, edit-check errors (`check_edit.py`), active peers (`coord.py`), Orchestrator plan handoffs/reviews (`orchestrator.py`), parallel/swarm hints (`parallel.py`), sandbox/context/error-loop hints (`speed.py`), plan-limit hints (`quota.py`; setting `quotaHints`), memory recall/hints (`memory_hints.py`), fact-grounding (`facts.py`), and objectivity hints (`objective.py`).
  - `guard.py` — `PreToolUse` safety guard (`run_command`, `write_file`, `edit_file`, `read_file`, `exit_plan_mode`): destructive commands, user-stated bans (with AST read-only `ssh … python3` exemption), `PreToolUse` `overwrite` auto-fixing for git flags and learned `BypassSandbox` commands, Orchestrator plan checks (`orchestrator.check_plan`), secret reads/writes, cross-agent stale-file protection with compact diff recovery (`coord.py`), permission-file protection (by file tools, sidecar control-plane blocks, and commands), and Bypass Mode: `auto_approve` for everything except `SYSTEM_RULES` (sudo, system folders, disks, power, autostart, keys, home or disk wipes, the agent's own permissions, scheduled sidecars) and the user's bans; text that runs on another machine or in a container (quoted strings and heredocs of `ssh`, `*ssh*` wrapper scripts such as `./deploy/ssh.sh`, `docker`/`podman`/`kubectl exec`) is checked without the rules that protect only this computer (`LOCAL_RULES`: system folders, protected files, sudo, autostart, the agent's own settings…) — wiping `/` or a disk, power, `kill -9 -1` and key reads still stop; `guard.py --test "<cmd>" --bypass`.
  - `check_edit.py` & `checks.py` — `PostToolUse` syntax and project-linter checks on written/edited files.
  - `stop.py` — `Stop` hook: honors `continuationActive` and Orchestrator read-only plan mode, prevents repeat `stop:background` nudges, checks open `task.md` items, syntax errors, unverified UI/mobile/code changes, untracked CI runs after push/PR, announce-only turns, agreed-without-looking replies, fact-checking of test/CI/deploy/perf claims, URLs, and numbers (`facts.py`), and end-of-work memory reminders.
  - `orchestrator.py` — Orchestrator phase helper: checks `exit_plan_mode` plans for active user bans & missing verification steps (`check_plan`), injects handoff/review reminders (`handoff_message`), and tracks read-only plan mode (`in_plan_mode`).
  - `conversation.py` & `compat.py` — incremental transcript parser (user messages, bans, full access, the Bypass Mode switch) and OS abstractions (file locks, atomic replace, LS process/port discovery, browser/Node lookup).
  - `gitcheck.py` — git/gh commands that would hang or fail in Antigravity's terminal (guard denies them with the working form), a rebase/merge/cherry-pick/revert/bisect left half done (Stop after the agent's own git command; SessionStart flags older ones) and conflict markers (an edit error in `checks.py`); setting `gitChecks`.
- `antigravity-plus/skills/update/scripts/update.py` — releases: SessionStart starts `update.py background` at most once a day (cache `~/.gemini/antigravity-plus/update.json`; a release = a higher `version` in plugin.json, its notes = «Antigravity Plus X.Y.Z: …» commit subjects) and tells the main agent once a day; `run` fast-forwards a clean clone (modules.json `source`) or downloads the GitHub archive into `~/.gemini/antigravity-plus/source`, snapshots the install into `previous/` for `rollback`, runs the source's install.py, restarts the usage sidecar (`ManageSidecar`) when server.mjs changed. Settings `updateCheck` (on), `autoUpdate` (off). Tests and CI set `AGP_UPDATE_CHECK=off`; `AGP_UPDATE_RAW|ARCHIVE|COMMITS` point the network at test files.
- `antigravity-plus/skills/<name>/` — `SKILL.md` instructions and helper scripts under `scripts/` (plus `skills/usage/pricing.json` for model rates, context windows, and compaction thresholds).
- `antigravity-plus/skills/lsp/scripts/lsp.py` — an LSP client for agents (Antigravity has no code-intelligence tool): finds the installed server per language (`LANGS`/`SERVERS`, `~/.gemini/antigravity-plus/lsp.json`) and the project root (`ROOTS`: outermost `pyrightconfig.json`/`buildServer.json`/`settings.gradle*`, else the nearest project file); a detached `lsp.py daemon` per (server, root) keeps it warm behind a Unix socket (TCP + token on Windows) in `~/.gemini/antigravity-plus/lsp/`, syncs changed files before each command, stops after `AGP_LSP_IDLE` (600 s), at most `AGP_LSP_MAX` (3). Positions are `<file>:<line> <name>`. `refs`/`calls` add a text cross-check of files the server didn't link. Hooks use `session_lines()` (session context), `edit_problems()` (check_edit: errors an edit added vs `git show HEAD:`, only from a running server) and `search_hint()` (instructions.py after two rg searches for symbols, `conversation.symbol_search()`); setting `lspChecks`.
- `antigravity-plus/agents/*.md` — read-only reviewers/researchers (`code-reviewer`, `security-auditor`, `explorer`, `researcher`) and write-capable specialists (`worker`, `debugger`, `test-writer`).
- `antigravity-plus/rules/*.md` — always-on rules: `AGENTS.md` (core), `FACTS.md` + `OBJECTIVE.md` (facts module), `MEMORY.md` (memory), `PARALLEL.md` (parallel), `GIT.md` (git).
- `modules.py` — the install-time modules: skills, agents, rules, sidecars each owns, the settings keys forced off without it (`off`), tools it needs, scripts kept even without it (`keep`), and bilingual detailed descriptions. `install.py` stages a filtered copy (rules lose table rows, comma lists and `<!-- needs:<skill> -->` lines for commands left out) and writes `modules.json`; `memory.settings()` applies its `off` keys.
- `antigravity-plus/sidecars/usage/` — Control Center 2.0 auxiliary pane UI (`sidecar.json`, `server.mjs`, `index.html`, `status.py`) serving session/7-day usage (`usage.py`), Antigravity quotas (`RetrieveUserQuotaSummary`), live workspace agents/bridge tasks/LSP daemons (`status.py`), safe coaching toggles (`/api/toggle` allowlist), LSP stop, update checks, and redacted `guard.log`.
- `claude-code/skills/antigravity/` — Claude Code's skill (`SKILL.md`: when to delegate, model tiers, brief, verification) and `scripts/delegate.py`: starts conversations through the language server's `agentapi new-conversation --model=<modelId>` / `send-message` (project from `~/.gemini/config/projects`, created for an unknown folder), waits with `WaitForConversationFullyIdle` while watching for `CORTEX_STEP_STATUS_WAITING` approvals, and reports from `GetCascadeTrajectorySteps`, `GetTrajectoryFileDiffs` and `GetCascadeTrajectoryGeneratorMetadata`. Task records: `~/.gemini/antigravity-plus/delegate/`. The hooks know delegated conversations by `conversation.DELEGATED_MARK` and skip setup, review, CI, recent-conversation and memory-saving nudges there. Talk while it works: the agent's `delegate.py ask|tell` only print a `{"to_claude_code": …}` JSON line; Claude Code's side (`listen()` → task record `chat`) reads it from the trajectory — the RUN_COMMAND output, or the SYSTEM_MESSAGE `agentMessage` of a command that went to the background; `watch` (one stdout line per event, for Claude Code's Monitor tool), `wait` (exit 4 on an open question) and `reply` (`agentapi send-message --title="Claude Code"`). A conversation whose summary is IDLE while `WaitForConversationFullyIdle` still blocks has ended its turn with its own background work running (a build, a subagent): `result`/`list` report it as `background`, not done (`idle_state()`, a 2 s probe), and `--model orchestrator` means Orchestrator (Carbon) although Antigravity lists Orchestrator (Neon) first (`fuzzy()` prefers the id with the fewest extra words). guard auto-approves only the installed script as one plain command (`talks_to_claude()`); Stop leaves an agent alone while `conversation.waiting_for_claude()`.
- `tests/` — standalone offline process tests (`test_*.py`) executed by `tests/run_tests.py`; `tests/probe/fake_lsp.py` is the fake language server of `test_lsp.py`.

## Conventions
- **Zero external Python dependencies:** keep all Python scripts compatible with Python 3.8+ (`from __future__ import annotations`, stdlib only) — hook PATH on macOS often resolves `/usr/bin/python3` (3.9), and CI runs Python 3.9 and 3.13 across Ubuntu, macOS, and Windows.
- **Cross-platform paths and locks:** use `hooks/compat.py` for file locking and atomic file replacement; pass `-X utf8` / explicit `encoding="utf-8"` for file and pipe I/O — every `subprocess` call with `text=True` also passes `encoding="utf-8", errors="replace"` (a Russian Windows decodes pipes as cp1251 otherwise, and the hooks print UTF-8), and no string may hold an escape Python warns about (`"C:\Windows"` in a docstring; use `r"""…"""`). `tests/test_names.py` checks both.
- **Public repository hygiene:** never include real hostnames, emails, private project names, bundle IDs, device names, or verbatim user chat quotes in code, tests, comments, or docs — use neutral synthetic examples.
- **Rule files:** every file in `antigravity-plus/rules/` requires `trigger: always_on` YAML frontmatter and must remain under Antigravity's 24 KB per-file limit.

## Gotchas
- Editing files in this repository does **not** update the live Antigravity installation until `./install.sh` is run.
- The sidecar SDK (`sidecar_sdk`) checks `X-Sidecar-Token` only on non-GET requests: register every Control Center API that returns or changes state as POST (`app.api(path, fn)`), never `'GET'`.
- Antigravity automations (verified in the 2.32.2 binary): `~/.gemini/config/sidecars/<id>/sidecar.json` with `"builtin": "schedule"`, `"args": ["CRON_TZ=<zone> <cron>", "agentapi", "new-conversation", "--", "<prompt>"]` (a list), `"restart_policy": "always"`, `display_name`, `agent_permissions` {`access_grants`, `workspace_uris`}; only the user enables one (Automations dashboard), and unattended runs deny every command not granted. The built-in `automation` skill's Quick Start still names `~/.gemini/jetski/sidecars` and object args — outdated. `/schedule-task` owns only `agp-*` ids; guard asks before any write there (`scheduled-sidecar`).
- `sidecars/usage/index.html`, `usage.py`, and `pricing.json` are read per request, whereas changes to `sidecars/usage/server.mjs` require restarting the `antigravity-plus/usage` sidecar via Language Server RPC (`ManageSidecar`).
- Antigravity's agent terminal (verified 2026-11-14): stdin/stdout/stderr are TTYs, `TERM=dumb`, `PAGER=cat`, `GIT_EDITOR=false` — an editor-wanting git command fails at once (`-c core.editor=…` can't override the variable; use `GIT_EDITOR=true git …`), keyboard prompts (`git add -p`, gh questions) hang.
- Hooks read settings through `skills/memory/scripts/memory.py`, so the memory module keeps that script installed even when it is left out (only its `SKILL.md` goes); skill-backed hook nudges check the skill's script exists (`stop.py`, `session_start.py`).
- pyright answers references from open files only until its «Found N source files» log line — `lsp.py` waits for it (`Session.ready`); a server that never says so would leave answers incomplete without an error. sourcekit-lsp sees an Xcode app's own code only through xcode-build-server (`buildServer.json`) and an index as fresh as the last build; kotlin-lsp needs the Gradle root as its workspace and leaves a JVM behind unless its whole process group is killed (`kill_tree`). Never start a server from a hook: `edit_problems()` only talks to a running daemon.
- Agent markdown (`agents/*.md`) goes through the installer's `filter_rules` too: a line marked `<!-- needs:<skill> -->` disappears without that skill — keep such additions on one line.
- `tests/test_names.py` uses `symtable`: in Python 3.9 a function named `top` (the name of CPython's module-level table) makes its parameters look global and fails the check — don't name a function `top`.
- Hooks must never crash or break a conversation on malformed input; `PreToolUse` returning `{}` means **deny** in Antigravity (use `{"decision": "allow"}` for pass-through).
- Bypass Mode is `bypassMode` {on, at, since, conversation, n} in `~/.gemini/antigravity-plus/settings.json`, switched only by a typed user message (`/bypass`, `/bypass off`; not a delegated brief, a subagent's task or `agentapi`, which the guard stops). A switch is applied once per conversation (`bypass_applied`) and only when its message is newer than the saved `at`, so an old «/bypass» never undoes a later «/bypass off».
- `delegate.py` runs from `~/.claude/skills/antigravity/scripts/` with a copy of `hooks/compat.py` next to it (the installer puts it there); its `MARK` must equal `conversation.DELEGATED_MARK`, and its `ANSWER` / `MESSAGE` / `FOLLOW_UP` openings must match `conversation.CLAUDE_SAYS` (`tests/test_delegate.py` checks both). Two commands from one model response can show up with the second step not filled in yet: the talk cursor (`talk_in()`) holds at an unfinished step, and every "finished" verdict re-reads the whole turn first.
- `usage.py` prices a conversation started through agentapi (no «Model Selection» message in its transcript) by `started_on()`: the bridge's task record, else `GetCascadeTrajectoryGeneratorMetadata` (only where `ANTIGRAVITY_LS_ADDRESS` + `ANTIGRAVITY_CSRF_TOKEN` are set — the side panel), cached in `~/.gemini/antigravity-plus/conversation-models.json`; only then `default_model`. Its `TIERS` list Antigravity's live `modelId`s (`GetCascadeModelConfigData`) — update them when Antigravity renames models; until then a label-based fallback picks the closest ones. Within a tier `pick()` reorders by `state_of()` of each quota group (`RetrieveUserQuotaSummary`: exhausted / tight / ok / spend from the weekly + 5-hour fractions and the week's pace); Claude Code's own limits (`claude_limits()`: `--claude-*` flags or the `statusline` record) only change `advice()`. Measured speeds come from `GetCascadeTrajectoryGeneratorMetadata` (`timeToFirstToken`, `streamingDuration`), cached 6 h in `~/.gemini/antigravity-plus/delegate/speeds.json`.
- Orchestrator (Carbon / Argon / Neon) (`gemini-pro-orchestrator`, `gemini-pro-orchestrator-argon`, `gemini-pro-orchestrator-neon`; Antigravity 2.32): the planner works in plan mode (reads files and runs probing commands, edits nothing) and hands its plan over with the `exit_plan_mode` tool; a SYSTEM_MESSAGE «Plan mode is off: this turn runs on the execution model» follows, and Gemini 4 Hydrogen carries the plan out until it hands back with `enter_plan_mode` (a `reply` from Claude Code doesn't hand back). Transcripts don't name a call's model: `usage.py` takes it from `GetCascadeTrajectoryGeneratorMetadata` where it can ask the language server (planner «Orchestrator (Carbon)», executor «Gemini 4 Hydrogen (Orchestrator)» = `gemini-flash-worker-agy`; a call's `stepIndices` start with its own PLANNER_RESPONSE step), else from those markers (`EXECUTION_RE`). Quota groups list «Orchestrator (Carbon)» whole, so `delegate.group_of()` matches the whole label as well as the family. Measure quota with `RetrieveUserQuotaSummary {"forceRefresh": true}`: the plain call answers from the language server's cache, refreshed every ~5 minutes (that is what made Orchestrator (Carbon) look ~7× cheaper than Carbon (High) on 2026-11-17 — it is only 10–15% cheaper); forced reads show every call booked within seconds at its API price (per token Hydrogen 1, Neon 2, Carbon ~4). Keep the account's other devices quiet while measuring, and count only bookings that fall in a run's own calls.
- Gemini 4 Neon (2026-11-18; `gemini-4-neon-low|medium|high|xhigh`, Antigravity's default model since) is priced $3 / $15 / $0.15 in `pricing.json`. Tiers since 0.27.0 come from a benchmark on 2.33.0 (2026-11-20: five tasks with hidden tests up to a fix in guard.py, 48 runs on 16 models, all right but Hydrogen (Low) once): `fast` Hydrogen (Low), `standard` Hydrogen (Medium), `strong` Neon (Medium) → Hydrogen (High) → Neon (High) → Orchestrator (Neon), `ultra` Carbon (High, its recommended effort) → Orchestrator (Carbon) → Carbon (Medium) → Argon (High) for complex, specific tasks (4–12× the time, never better on the benchmark's), `claude` Sonnet → Opus; `claude` and `ultra` keep their order. Every model in no tier is «Experimental» (`delegate.EXPERIMENTAL`: a word on when it may fit; a new model shows up with Antigravity's own description). Antigravity's Claude group costs ~2.5% of its week per API $ (Gemini ~0.042%). Context windows (verified on 2.33.0, 2026-11-20): `maxContextTokens` in generator metadata and in the agent-state stream (`StreamAgentStateUpdates` → `contextWindowUsage`) is 512000 for the whole Gemini 4 family since 2026-11-16, 256000 for Gemini 3.x Flash, 128000 for Flash-Lite, 840000 for Claude 5.5 (`checkpoint-variant` claude-1m_840k); Antigravity compacts as soon as the next call won't fit, by the model-reported count (flag `use-model-reported-token-count`) — no call ever went past the window (max 511.8k of 512k, 256.05k of 256k), a big tool result can trigger it earlier. `pricing.json` `context_window` = that window (no `compaction_threshold`), `speed.ctx_limits()` warns at 200k / 440k on Gemini 4, 150k / 220k on 3.x. Users can compact on demand with the built-in `/compact` (2.33).
- A `systemMessage` injected by SessionStart/PreInvocation stays in the conversation until compaction (Antigravity 2.32 hook docs; the deprecated `ephemeralMessage` is converted into one), and the model re-reads it on every later call: inject a hint only when something changed — `<user_instructions>` long-turn refreshers come at most every 100 steps, background-command hints once per conversation, `<other_agents>` when the set of agents changes.
